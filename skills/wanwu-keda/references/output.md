# 输出组装

模块是可选的，不是模板。**先决定问题需要哪几个模块，再写**；写完删掉没有实际内容的模块。

## 三档与模块配额

| 档位 | 模块数 | 长度参考 | 说明 |
| --- | --- | --- | --- |
| 直答 | 0～1 | 1～2 段 | 直接给答案 + 必要前提。可加一句「这题不需要拆解」 |
| 标准 | 4～6 | 800～1800 字 | 选真正需要的模块，跳过无关的 |
| 深度 | 8～10 | 2500～5000 字，可分轮 | 多领域交错、证据冲突、用户要求展开 |

**篇幅不是深度的证据。** 若某个模块写完只有一句套话，删掉它并表示「这一点没有更多可说的」。

## 十个模块

**1. 问题重新定义**
用户原话 → 我理解的问句 → 改写后的可答形式。若无需改写，一句话带过。必须保留原话，让用户能看出我改了哪里。

**2. 核心概念与隐含前提**
关键术语的用法（多义的列出差异）、问句里已经接受的前提、每个前提的证据状态。前提有问题时在这里指出，不要留到最后。

**3. 问题性质与可回答边界**
这题是事实／定义／因果／价值／政策／动机（可多标）。混合型在这里拆子问题。**明确说出「哪一部分无法由证据回答」**——这是本 skill 最该说的话之一。

**4. 最相关学科与分析方法**
3～6 个，每个说明「它提供什么」：一个分析方法、一条硬约束、或一个关键变量。**不为凑数列学科**，无关的直接写「此题不涉及」。引用学科时看 `facets.md` 对应条目的分析工具，不要只写学科名。

**5. 基础事实与证据**
可核验的事实，按证据状态标注。优先给量级和方向（多少、多大、朝哪边），而不是形容词。区分原始观察与转述结论。

**6. 机制与因果关系**
因果链怎么走、有哪些替代解释、能排除哪几条。若无法确立因果，就说「目前只能确认相关」。

**7. 竞争性解释及最强反驳**
主要解释 2～3 个。每个给最强支持、最强反驳、一个具体反例、以及「什么证据能推翻它」。不搞伪平衡，用证据差距表述（见 engines.md 3.3）。

**8. 认知盲点审计**
2～5 条，每条五项齐全（见 engines.md 4.2）。明确区分「从你话里读出来的」和「我推测的」。

**9. 不确定性与知识边界**
我缺什么信息、哪些是学派之争我取了立场、哪些超出任何学科的公认边界、哪些是时效性事实可能已变。**这一模块不能删**，深度档至少三行，标准档至少一行。

**10. 综合结论及仍待解决的问题**
给结论时标清它的性质（事实性结论／条件性结论／建议／只是倾向）。一句话说「这个结论在什么条件下会改变」。列出 1～3 个仍待解决的问题，以及解决它们需要什么观测。

## 模块选择

| 问题特征 | 必备模块 |
| --- | --- |
| 概念含混或价值词多 | 2、3、8 |
| 有明确事实争议 | 5、6、7、9 |
| 问「为什么」 | 6、7（至少两个竞争解释） |
| 问「该不该」 | 3、5、8、10（价值部分明说不可由证据裁决） |
| 问「会不会」 | 5、6、9（给区间与条件，不给单点预测） |
| 用户情绪化或自我指责 | 1、8（先重构问题，不做诊断） |
| 时效性强（政策、价格、技术） | 5 必须先核查并标日期 |

## 直答档怎么写

- 先给答案，再给前提条件
- 一句话说明为什么不需要拆解（定义清楚 / 事实稳定 / 无实质分歧）
- 结束时给一句「如果你要问的其实是 X，告诉我」——留出改口的余地
- 不硬凑模块，不写「以下是十个角度的分析」

## 写作禁令

- 不用「众所周知」「显然」「本质上」「其实很简单」跳过论证
- 不用排比堆学科名
- 不给用户贴心理学标签，不做人格诊断
- 不写「一方面……另一方面……」却不说明证据差距
- 不为填模块而写段落
- 不把「可能」「或许」当护身符：要么说清不确定在哪，要么给出条件

## 长度与续写

- 深度档超过单轮上限：分轮输出，每轮说明本轮覆盖哪些模块、还剩哪些
- 被截断时明确告知断点，不假装写完
- 用户说「深挖 X」：只写 X 对应模块，走 `facets.md` 的下钻模板（子领域 → 学派谱系 → 关键案例 → 争议现状）
- 用户说「直接说结论」：只写模块 10 与必要的 9
