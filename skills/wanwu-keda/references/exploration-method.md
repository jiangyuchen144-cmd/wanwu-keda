# 问题探索方法

本文件定义如何把用户提出的问题转化为值得研究、能够逐步检验的探索路径。它是方法参考，不是固定输出模板。

## 1. 先判断问题类型

先识别主要任务，可同时属于多种类型：

- **事实型**：某事是否发生、是什么、何时发生。
- **定义型**：一个概念是什么意思、边界在哪里。
- **解释型**：某种现象为什么发生、通过什么机制发生。
- **比较型**：两个或多个对象有什么相同与不同。
- **预测型**：未来可能发生什么，概率和条件是什么。
- **评价型**：某事是否好、合理、公平或值得。
- **决策型**：在目标、约束和风险下应该怎么做。
- **探索型**：用户尚未确定具体问题，希望扩展理解。

不要因为问题复杂就默认它是跨学科问题。先确定真正需要解决的认知任务。

## 2. 拆解问题，而不是复述问题

检查以下项目：

1. 核心名词是否有多个定义？
2. 关键动词是否隐藏了因果假设？例如“导致”“造成”“决定”。
3. 问题是否预设某种现象存在、普遍或可以被解释？
4. 是否把不同时间尺度、群体或层级混在一起？
5. 是否把描述性问题与规范性问题混在一起？
6. 是否把一个大问题误当成一个单一问题？

将发现分成：
- **必须澄清**：不澄清会导致回答方向明显不同。
- **可以暂定**：可先说明采用的工作定义并继续。
- **值得探索**：不妨碍当前回答，但可能打开重要的新方向。

只有必须澄清且无法合理暂定时，才优先向用户提问。其他情况先说明假设并推进分析。

## 3. 扩展问题空间

从不同角度寻找“用户还没想到要问什么”。以下是启发式清单，不是必须全部覆盖：

- 概念：还有哪些定义或分类方式？
- 前提：问题默认了哪些尚未证明的事实？
- 变量：哪些因素可能改变结论？
- 机制：结果通过什么过程产生？
- 层级：个人、家庭、组织、市场、制度、国家或全球层面是否不同？
- 时间：短期与长期是否相反？
- 分布：平均值是否掩盖群体差异？
- 反例：哪些案例不符合初步解释？
- 利益相关者：谁受影响、谁有决策权、谁承担成本？
- 价值：判断“好坏”使用了什么标准？
- 方法：什么观察或研究设计能回答这个问题？

### 方向排序

对候选方向按以下问题排序：

- 如果这个方向的答案不同，是否会改变主要结论？
- 它是否能解释目前解释不了的现象？
- 是否存在可获得的证据？
- 它是否能区分两个竞争性解释？
- 它是否与用户的目标直接相关？

优先选择少数高价值方向。不要把“覆盖更多角度”当成质量本身。

## 4. 识别因果结构

当问题涉及原因、影响或机制时，至少检查：

- 相关性是否被误读为因果关系？
- 是否存在反向因果？
- 是否存在共同原因或混杂变量？
- 是否存在选择偏差、幸存者偏差或测量偏差？
- 是否有中介变量、调节变量或反馈环？
- 是否存在多个充分原因或多个必要条件？
- 因果关系是否随时间、群体和环境变化？

把因果主张写成可检查的链条，例如：

`条件 A → 机制 M → 结果 B`

并指出链条中哪些环节有证据，哪些只是推测。必要时考虑替代路径。

## 5. 区分定义、描述与解释

尤其注意以下三种陈述：

- **定义**：我们把 X 称为什么。
- **描述**：观察到 X 具有哪些特征。
- **解释**：哪些机制导致 X 出现。

不能用定义代替因果解释，也不能把指标当成现象本身。

例如，如果把贫穷定义为“能力和机会不足”，再说“人因为能力和机会不足而贫穷”，可能只是重复定义。要解释成因，需要进一步测量资源、制度、健康、教育、市场条件等变量，并说明机制。

## 6. 形成阶段性认知地图

对复杂探索，阶段性地图可以包含：

- 当前问题的工作定义；
- 已确认的基础事实；
- 关键变量和可能机制；
- 主要竞争性解释；
- 解释之间的冲突或互补；
- 当前最强的证据；
- 尚未解决的关键问题；
- 下一步最有信息价值的探索。

认知地图是当前状态的快照，不是终局结论。新证据出现时应允许重画。
