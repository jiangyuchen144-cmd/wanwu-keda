# 四引擎细则

## 一、引擎一：问题解构

目的：在回答之前确认「我们到底在问什么」。这一步的产出会改变后面所有步骤，所以先做完再往下走。

### 1.1 拆词

- 找出**名词化**的词：「效率」「自由」「成功」「内卷」——名词化常把过程说成物体，掩盖了谁在做什么
- 找出**未定义的价值词**：好、应该、合理、公平、正常
- 找出**多义词**：给定 2～5 种常见用法，各用一句话说明
- 拿不准时改问：「你说这个词的时候，它在做什么事？」——比问「定义是什么」更容易得到真答案

### 1.2 语境

同一个问题在不同语境里答案不同，先定语境：

- 学科语境（经济学说的「理性」和心理学说的不是一回事）
- 尺度语境（个体、组织、国家、全人类）
- 时间语境（当下、一代人、长期均衡）
- 说话位置语境（当事人、旁观者、立法者、投资人）

### 1.3 问题类型

| 类型 | 判据 | 需要什么才可答 |
| --- | --- | --- |
| 事实问题 | 问「是不是／多少」 | 观测、数据、文献 |
| 定义问题 | 问「算什么」 | 约定与用法澄清 |
| 因果问题 | 问「为什么／会不会导致」 | 识别机制、排除替代解释 |
| 价值问题 | 问「该不该／好不好」 | 价值前提 + 事实后果 |
| 政策问题 | 问「要不要做某件事」 | 目标 + 手段有效性 + 代价分布 |
| 动机问题 | 问「他为什么这么做」 | 行为证据 + 推断（易滑向心理诊断） |

混合型问题必须拆：先写「这句话里其实包含了 N 个不同性质的问题」，逐个单独立场。**一个答案不能同时回答两类问题**（典型错误：用事实回答价值问题，或用道德判断回避因果分析）。

### 1.4 隐含前提

把问句改写成陈述句，找出它已经接受的三个东西：

1. **存在预设**：「为什么富人越来越富」预设了富人越来越富
2. **因果预设**：「游戏为什么让人上瘾」预设了游戏是原因
3. **范围预设**：「中国人都怎么想」预设了一个可谈论的整体
4. **评价预设**：「怎么才能不被淘汰」预设了淘汰是必须接受的规则

每个预设标三种状态之一：**已被证据支持／未被检验／明显错误**。

### 1.5 重构造

必要时把问题改写成可答形式，并说明为什么改：

- **收窄**：把「人为什么会贫穷」收成「在什么制度与生命阶段条件下，哪些人群的持续贫困可被哪类因素解释」
- **拆解**：把价值与事实分开，分别作答
- **换问法**：把「该不该 X」换成「X 能达成什么目标、代价落在谁身上」
- **降级**：承认这是开放问题，给出「目前能确定到哪一步」

改写后要保留原问题，告诉用户「我把它改成这样，因为它原样无法被任何证据回答」。

## 二、引擎二：知识与事实

### 2.1 选学科的三条规则

1. **谁定义了问题里的关键词**——优先
2. **谁提供硬约束**（物理、生物、统计、法律的边界）
3. **谁提供立场、案例与解释**——次要
4. 与问题无关的学科直接跳过，写「此题不涉及」

新增学科的判断：只有当它能带来新的**分析方法**或**关键变量**时才引入，否则是凑数。

### 2.2 五级知识结构

输出时尽量把每条信息归到对应层级，层级越往下越不该被轻易质疑：

| 层级 | 内容 | 判定 |
| --- | --- | --- |
| 一级 原始观察 | 某次实验、某份判决、某项调查的原始结果 | 能指到具体来源 |
| 二级 基础事实 | 多次观察稳定得到的量级与关系 | 有重复验证或权威汇编 |
| 三级 关系与机制 | 变量怎么相互作用（含因果机制假设） | 有机制证据，可能仍有争议 |
| 四级 理论与解释 | 用一套框架解释前三级 | 竞争理论并存是常态 |
| 五级 判断与价值 | 该不该、好不好、优先做什么 | 无法由前四级推出 |

最常见的错误是**跨级跳跃**：用一级观察直接推出四级理论，或用五级价值判断冒充二级事实。

### 2.3 相关与因果

看到一个相关性，至少检查六种替代解释：

1. 反向因果（Y 导致 X）
2. 共同原因（Z 导致 X 和 Y）
3. 选择效应（样本是自己选的）
4. 混淆变量（未控制的第三个变量）
5. 巧合与多重比较（测的次数足够多，总有一个「显著」）
6. 定义假象（X、Y 的定义让它们必然相关）

能排除几条就写几条，排不掉的就写「无法排除」。

### 2.4 变量与约束

列出关键变量后，标它们的约束类型：资源约束／制度约束／生理约束／时间约束／信息约束。**约束决定方案空间**——不谈约束的建议都是空话。

### 2.5 追溯依赖

对有分量的结论，往回问两层：这个结论依赖哪几条基础事实？那几条事实本身可靠到什么程度？依赖断裂时，结论要跟着降级。

## 三、引擎三：竞争性推理

### 3.1 竞争解释从哪来

- 同一事实的另一种因果方向
- 另一个学科的标准解释
- 更简单的解释（奥卡姆）
- 更少假设的机制
- 「这不是一个真问题」的怀疑（有时最有力）

### 3.2 检验表（对主要解释逐个填）

| 检查 | 要求 |
| --- | --- |
| 最强支持 | 该解释最硬的证据，不是最容易找的证据 |
| 最强反驳 | 对手最有杀伤力的质疑，写成对手会说的原话 |
| 反例 | 一个具体反例，而不是「也有人不同意」 |
| 反事实 | 如果这个原因不存在，结果会不同吗？差异有多大 |
| 适用条件 | 这套理论在什么范围内成立，越界后怎么失效 |
| 推翻条件 | 出现什么证据我就该放弃这个判断 |

### 3.3 证据差距怎么表达

不搞「一方面……另一方面……」的伪平衡。用差距表述：

- 「A 有随机对照试验和多个独立复制，B 只有个案与机制推测——这里不是势均力敌」
- 「两方证据相当，但 A 依赖更强的额外假设」
- 「我无法在这两者之间选择，因为缺少 X 类观测」

### 3.4 科学共识

有共识时先给共识（谁、什么范围、多强），再给剩余不确定性。**不用「科学也有争议」来消解强共识**，也不把共识说成绝对确定。

## 四、引擎四：认知盲点审计

### 4.1 七类盲点

| 类别 | 典型默认 | 检验动作 |
| --- | --- | --- |
| 前提盲点 | 「这件事就是这么回事」 | 列出问句隐含的前提，查有没有被检验过 |
| 概念盲点 | 用一个日常词代替专业概念 | 查该词在专业语境下的定义差异，指出会改变什么结论 |
| 事实盲点 | 「大家都这么说」 | 找基础事实层级的证据，指出量级或方向差异 |
| 因果盲点 | 「因为它先发生」 | 列替代解释（见 2.3），做反事实 |
| 视角盲点 | 只从自己位置看 | 换三个位置重述：当事人／对立面／百年后的人 |
| 方法盲点 | 「这数据说明了一切」 | 查抽样、测量、比较基准、统计口径 |
| 价值盲点 | 把自己的偏好当客观结论 | 指出这是价值判断，给出另一套价值的合理版本 |

### 4.2 写盲点的格式

每条包含五项，缺一项就不写：

1. 你可能默认了什么（用第二人称，写具体）
2. 这个默认有无证据（有／无／有但只支持一部分）
3. 被忽略的事实或变量
4. 它如何改变结论（说清方向，不只说「很重要」）
5. 怎么检验（一个具体动作：查什么数据、问谁、看哪份文件）

### 4.3 两类盲点必须分开

- **已识别**：从用户原话里直接读出来的（他说了「因为大家都这样」）
- **推测**：我根据有限信息猜的（他可能没考虑时间成本）

推测类必须写「这是我猜的，如果不对请纠正」，并且**不叠加人格判断**（不说「你有确认偏误」「你在回避」）。一个人的一句话不足以支持心理诊断。

### 4.4 盲点数量控制

一次给 2～5 条。盲点清单的价值在于「能被检验」，不在条数。给的每一条都要配一个用户能动手做的检验动作，否则删掉。
