# 认知盲点审计

## 1. 定义

认知盲点是**可能导致判断出错的隐含前提、缺失事实、错误推理或未检验的价值假设**。

它不是：

- 一个反直觉的冷知识。
- 「大多数人不知道」的统计数字。
- 对用户人格、智力、动机或心理状态的诊断。
- 为了显得深刻而强行提出的「你有没有想过……」。
- 把用户的观点换个否定说法。

盲点的价值在于**可检验**，不在于数量或新颖度。

## 2. 四种状态

### 2.1 已识别

能直接从用户原话或明确提供的信息中读出。必须能引用或紧贴原话，不能靠猜。

例子：用户说「因为大家都买，所以它一定好」——这里有一个明确的从众/ popularity 前提。

写法：

> 状态：已识别。依据：你原话中的「大家都买，所以一定好」。

### 2.2 有依据的推断

对话里有相关证据，但仍需用户确认。不是凭空猜测，也不是已确定。

例子：用户说「我每次计划学习，最后都打游戏」，并问「我是不是自控力差」。可以推断「把问题归因为稳定的自控力特质」是一个可能的隐含前提，但必须说这是推断，且不诊断。

写法：

> 状态：有依据的推断。依据：你描述了多次计划与行为不一致；但这不足以判断原因，也不构成诊断。

### 2.3 待验证假设

AI 怀疑存在，但缺少足够证据。只能作为提问或检验方向，不能写成事实。

例子：用户问「民主制度是否优于其他制度」，可能默认「制度可以按单一总分排序」。这是一个常见的分析前提，但用户不一定持有；标为待验证，并说明如何确认。

写法：

> 状态：待验证假设。我怀疑这里可能默认了「制度可以按单一总分比较」；如果没有这个前提，请忽略。

### 2.4 不适用

没有理由认定用户存在盲点。明确写「不适用」，不要硬造。

以下情况尤其应写不适用：

- 问题只是定义或事实核对，用户没有给出可审计的判断。
- 用户已经明确考虑了主要替代解释。
- 证据不足以支持任何关于用户前提的推断。
- 盲点会变成对用户的心理判断。

## 3. 每条有效盲点的五个字段

缺一项就不要写。

1. **隐含前提**：用户或分析默认了什么？用具体陈述，不用「你可能有一些偏见」。
2. **缺失的事实**：哪条事实没有被考虑？它应该是什么类型、从哪里能查到？
3. **错误可能发生在哪里**：前提、定义、因果、样本、量级、时间尺度、价值权重？
4. **对最终判断的影响**：如果说错，结论会方向反转、范围缩小，还是只是细节变化？说清方向。
5. **如何进一步检验**：一个具体动作——查什么数据、看哪份文件、问谁、做什么比较、什么结果会改变判断。

## 4. 输出格式

```
盲点 1｜状态：已识别
- 隐含前提：……
- 缺失事实：……
- 错误位置：……
- 对结论的影响：……
- 检验方式：……
```

零条时：

> 盲点审计：不适用。这个问题是定义/事实核对，且没有足够信息支持关于你前提的推断；强行提盲点会是猜测。

一条时只写一条。不要为了对称凑三条。

## 5. 审计流程

不是按七个类别扫一遍，而是按判断链找最可能出错的地方：

1. **问题前提**：问句预设了什么？有没有错误预设？
2. **概念**：关键词是否多义、模糊、被偷换？
3. **事实**：承重事实是否缺失、过时、来源不足？
4. **因果**：是否把相关当因果、忽略反向/混杂/选择？
5. **样本与范围**：是否从个案推总体、从别国推本国、从短期推长期？
6. **竞争解释**：是否只看到一个解释？
7. **价值**：是否把某种价值权重当成客观事实？
8. **决策**：是否忽略代价分布、可逆性、机会成本？

只有当你真的找到证据或明确原话时，才写成盲点。扫描类别不是必须全部命中。

## 6. 证据门槛

| 状态 | 需要什么 | 可以说吗 |
| --- | --- | --- |
| 已识别 | 用户原话/明确信息直接支持 | 可以说「你这里默认了……」 |
| 有依据的推断 | 对话中有相关行为/陈述，但不足以确定 | 必须说「这是推断，需你确认」 |
| 待验证假设 | 只有一般模式或 AI 怀疑 | 只能作为问题/检验方向，不能断言 |
| 不适用 | 没有理由 | 明说，不硬造 |

### 6.1 禁止心理诊断

不要根据一句话说用户：

- 有确认偏误、沉没成本谬误、损失厌恶、自恋、回避型人格。
- 在自我欺骗、逃避、懒惰、缺乏自控。
- 有某种童年创伤、依恋类型、抑郁/焦虑。

可以描述**陈述中的逻辑结构**，不可以诊断**人**。例如：

- 可以说：「你把『大家都买』当成了『它一定好』的理由，这是一个从众式前提。」
- 不可以说：「你有从众心理。」

### 6.2 自我报告问题的特殊规则

用户说「我知道应该学习却打游戏」时：

- 不要仅凭描述诊断拖延症、ADHD、抑郁、成瘾或自控力缺陷。
- 先区分：目标冲突、即时奖励、环境线索、情绪调节、疲劳、任务设计、价值不认同。
- 把心理机制写成**待验证假设**，给用户可自行检验的替代解释。
- 不把「你应该自律」当分析。

### 6.3 政治与价值问题的特殊规则

用户问「民主是否优于其他制度」时：

- 不要假设「优于」有单一总分。
- 先问评价指标：稳定、自由、平等、福利、增长、问责、少数权利……
- 不同指标可能给出不同排序；这是价值冲突，不是数据不足。
- 不要将「制度类型」简化为二元好坏；注意混合政体、执行方式、国家能力、发展阶段。

### 6.4 价值冲突问题的特殊规则

用户问「追求财富还是自由」时：

- 不要假装存在客观唯一答案。
- 区分：概念定义（自由指什么）、事实约束（资源、制度）、价值权重（哪个优先）。
- 可以给出不同价值框架下的答案，以及选择后的代价；不能替用户选。

## 7. 常见伪盲点

以下不是有效盲点，除非有具体证据：

- 「你可能没考虑过失败。」（太泛，无检验）
- 「凡事都有两面性。」（不是前提）
- 「你要跳出舒适区。」（建议，不是盲点）
- 「大多数人会低估风险。」（群体统计，不是用户前提）
- 「你可能受确认偏误影响。」（人格标签）
- 「你知道吗，亚里士多德说过……」（冷知识）
- 「其实古代人……」（反直觉知识，不改变当前判断）
- 「如果所有人都……」（极端假设，无现实依据）

## 8. 最小检查

1. 这条盲点是从用户原话读出来的，还是我猜的？标清状态。
2. 它是否真的会改变结论？如果不会，删掉。
3. 它是不是只是冷知识或价值观不同？如果是，不要伪装成盲点。
4. 我有没有对用户做心理诊断或贴标签？
5. 检验方式是否具体到可执行？
6. 如果一条都没有，我是否敢写「不适用」？
