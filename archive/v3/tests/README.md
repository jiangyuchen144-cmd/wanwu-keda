# 测试方法

## 目的

不是证明 Skill「表现很好」，而是检查它在九个不同结构的问题上是否真的：

- 不把简单问题过度分析；
- 能找到复杂问题的关键事实；
- 区分事实、理论、因果推断与价值判断；
- 让重要结论可追溯；
- 识别隐含前提；
- 主动寻找反证；
- 发现真实盲点，而不是制造盲点；
- 承认不知道；
- 不对用户做心理诊断；
- 不把政治制度或价值选择简化成单一优劣排序。

## 流程

1. **生成**：对每个问题启动一个独立 agent。只给它问题、Skill 路径和输出路径；不提供预期答案、不提示「应该选什么模式」。
2. **保存原稿**：生成结果原样写入 `tests/drafts/qN.md`。
3. **独立审查**：另起一个没有参与生成的 agent，按 `review.md` 的十项检查审查原稿；把修正后的答案写入 `tests/outputs/qN.md`，审查记录写入 `tests/reviews/qN.md`。
4. **差异**：`tests/test-report.md` 记录原稿与修正稿的实际差异；不隐藏失败。
5. **人工复核**：对关键事实和来源做抽查；不能核实的来源标为未核实。

## 产物

- `drafts/`：生成原稿（不改动）
- `outputs/`：审查后答案
- `reviews/`：十项审查记录与实际修改
- `test-report.md`：九题汇总、通过项、失败案例
- `manual-source-check.md`：外部数字的人工抽查
- `skill-hash.txt`：测试时技能文件哈希

## 限制

- 这是提示词技能，不是确定性程序；测试结果只说明这些样本上的行为，不保证所有问题。
- 生成与审查都可能犯错；独立审查降低但不能消除错误。
- Agent 可使用的检索能力取决于运行环境；未联网核验的事实必须标出。
- 测试问题数量有限，不能覆盖所有领域。
