# 独立审查

## 1. 为什么独立

生成答案时的目标通常是「把它写出来」；审查时的目标必须是「找出它错在哪」。同一个思维过程连续做两件事，容易为自己的结构辩护。

独立审查不是重新写一篇更长的答案，而是：

1. 把草稿当作别人的稿子读。
2. 先找阻断性错误，再找细节。
3. 对每条重要主张核对依据，而不是欣赏表达。
4. 发现问题后改答案；改不动就降级或标未解决。

单模型环境下，至少另起一次检查，不引用生成时的自我解释。条件允许时，用另一个模型或另一个 agent 做审查。

## 2. 十项检查

### 2.1 事实是否准确

- 关键数字、日期、人名、法律条文、研究结论是否与来源一致？
- 有没有把估计值写成确定值？
- 有没有把「相关」写成「因果」？
- 有没有把某国/某群体/某时期的结果外推到别处？
- 事实是否过时？来源日期是什么？

失败信号：出现「众所周知」「研究表明」但无具体来源；数字没有口径；时间范围模糊。

### 2.2 来源是否真实

- 链接能打开吗？标题与内容一致吗？
- 来源真的支持该主张，还是只支持一个更弱的版本？
- 是原始来源还是二手转述？
- 作者/机构是否有相关资质或利益冲突？
- 有没有编造、错配、张冠李戴？

失败信号：只有「某研究」；链接指向首页/搜索页；引用与主张方向相反；来源日期不明。

处理：不能核实就删掉具体断言，或降为「未核验线索」；不能保留一个假链接。

### 2.3 推理是否成立

- 前提是否为真？推理形式是否有效？
- 有没有把必要条件当充分条件？
- 有没有从个案推总体、从短期推长期？
- 有没有循环论证、偷换概念、虚假二分？
- 结论是否比前提支持的更强？

失败信号：「因此必然」「这证明了」；前提里已经包含结论；用定义代替经验发现。

### 2.4 是否有隐藏假设

- 从事实到结论，中间默认了什么？
- 这些假设有没有被检验？
- 如果假设不成立，结论会怎样？
- 有没有把价值假设伪装成事实假设？

失败信号：「在其他条件不变的情况下」但不说明哪些条件；建议依赖「执行会到位」「人们会理性反应」等未验证前提。

### 2.5 是否有因果错误

- 反向因果？
- 共同原因/混杂？
- 选择效应？
- 测量或定义造成的相关？
- 生态谬误（群体数据推个体）？
- 回归均值、幸存者偏差、基础率忽略？
- 效应量是否支持结论？

失败信号：只有时间先后；只有一个案例；没有对照组；用机制故事代替识别策略。

### 2.6 是否遗漏重要解释

- 有没有至少一个合理的竞争解释？
- 有没有把弱解释当唯一解释？
- 有没有忽略「问题本身有错」的可能？
- 有没有忽略价值框架差异？

失败信号：解释只有一个，且与作者偏好一致；竞争解释被稻草人化；把「我不认同」当「已被排除」。

### 2.7 是否错误夸大确定性

- 证据状态与措辞是否匹配？
- 「可能」是否被写成「会」？
- 「强证据」是否被写成「证明」？
- 有没有把共识说成绝对，或把争议说成定论？
- 有没有给单点预测而非区间/条件？

失败信号：「必然」「一定」「毫无疑问」「科学已经证明」；弱证据却给强建议。

### 2.8 是否强行制造认知盲点

- 盲点是否有用户原话或明确信息支持？
- 是否把冷知识、价值观差异、人格标签伪装成盲点？
- 是否对用户做心理诊断？
- 是否为了凑数写「你可能没考虑……」？
- 零条时是否敢写「不适用」？

失败信号：每条盲点都很泛；用第二人称断言人格；盲点与结论无关。

### 2.9 是否使用了不相关的学科

- 每个领域是否提供了具体工具、变量或硬约束？
- 有没有为了显得全面而列学科？
- 有没有用学科名称代替分析？
- 有没有把同一工具换三个名字重复？
- 是否应该用矩阵外领域却没敢用？

失败信号：领域列表很长，但后文没有用到；每个领域只出现一次；用「从哲学、经济学、社会学看」开头却无实质差异。

### 2.10 结论是否超出证据支持的范围

- 结论的适用范围是否写清？
- 有没有从「在 X 条件下」推到「普遍」？
- 建议是否依赖未说明的价值权重？
- 有没有把「目前无法区分」写成「我选 A」？
- 有没有把「不知道」包装成「需要进一步研究」？

失败信号：结论比证据大一圈；建议没有代价分析；价值判断冒充事实。

## 3. 审查等级

| 等级 | 含义 | 动作 |
| --- | --- | --- |
| 阻断 | 关键事实错误、来源造假、因果推断不成立、结论会造成高风险误导 | 必须改；改不了就不输出该结论 |
| 重要 | 遗漏竞争解释、确定性夸大、盲点诊断化、学科凑数 | 必须改或明确降级 |
| 轻微 | 表述、格式、非关键细节 | 可改；不改不影响结论 |

不要用「已提醒读者」代替修正阻断错误。

## 4. 修正协议

1. **定位**：标出问题对应的主张/段落。
2. **改事实**：核对来源；错了就改，缺了就补，补不到就删或降级。
3. **改推理**：补假设、缩范围、换更强的证据，或把结论改弱。
4. **改结构**：删掉无关学科、空模块、伪盲点。
5. **再审查**：修改后重新过一遍受影响的检查项。
6. **记录**：深度模式可写「审查后修正」，说明改了什么、为什么；不要写成长篇自我批评。

### 4.1 不能做的事

- 只在结尾加「以上仅供参考」。
- 发现错误后保留原结论，只补充「也有不同观点」。
- 把「证据不足」写成「学界尚有争议」而不说明争议在哪。
- 把「我不知道」改写成「需要进一步研究」来显得专业。
- 删除错误但不说明结论已改变，让读者以为一开始就是这个结论。

### 4.2 修正示例

- 原文：「研究证明 X 导致 Y。」
- 审查：只有横断面相关，无因果识别；来源是二手报道。
- 修正：「X 与 Y 相关（`[性质:经验关系 | 证据:中等证据 | 推理:归纳]`）；目前不能确定因果方向。来源 S1 是二手报道，原文未核实。」
- 不是：「X 可能影响 Y（仅供参考）。」

## 5. 审查输出

审查者给生成者的记录：

```
审查结论：通过／修改后通过／阻断
阻断问题：
- …（对应检查项、证据、修改要求）
重要问题：
- …
已修正：
- …
剩余未解决：
- …（为什么不能解决，对读者的影响）
```

最终答案不必展示全部审查过程。深度模式可附简短「审查后修正」；快速模式只改，不附。

## 6. 自审问题

1. 如果我最强的证据是错的，结论还成立吗？
2. 我有没有为了让答案完整而写了自己不相信的话？
3. 我有没有把用户的偏好当成事实？
4. 我有没有因为某个学科「应该相关」而用它？
5. 我有没有因为怕说不知道而给了一个更确定的答案？
6. 这条建议如果被用户当真，最坏会怎样？
7. 我有没有把「无法区分」硬选成一个答案？
8. 我有没有对用户进行心理诊断？
9. 我有没有用「免责声明」代替修正？
